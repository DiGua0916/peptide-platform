Ad Brain 店铺接口文档

版本：peptide-core 0.34.17 · 2026-11-26 · 适用于 VialCove 全部店铺（0.34.13 起可用，0.34.17 新增内容见“更新记录”）

Ad Brain 的服务器通过这组接口直接和每家店对接：读取素材选项、给新素材发编号和投放链接、改落地页、把没登记的广告归到素材、删除素材，以及按日期区间拉取素材效果、全店漏斗、人群画像和脱敏订单。

每家店是独立的接口：地址、密钥都按店分开。要接哪家店，就用哪家店的配置。

1. 拿到配置

平台所有者在总后台 → Ad Brain 接口页面给店铺开启后，点「复制整份配置」，得到下面这样的 JSON：

{
  "stores": [
    {
      "store": "老毛",
      "site": "korgavex.com",
      "base_url": "https://www.korgavex.com/wp-json/peptide/v1/adbrain/",
      "secret": "（64 位十六进制密钥）"
    }
  ]
}
字段含义
store店铺名，只用于显示
site请求头 X-AdBrain-Site 填它
base_url接口根地址，后面接 options、creatives/issue 等
secret这家店的签名密钥，只放在 Ad Brain 服务器上，不要放进浏览器或前端代码
密钥在总后台点「重新生成」后，旧密钥立刻失效，要换成新配置。店铺被「关闭」后，所有接口返回 503。

如果服务器访问 /wp-json/ 不方便，可以用等价写法：https://www.店铺域名/?rest_route=/peptide/v1/adbrain/options，签名不变。

2. 签名规则（所有接口都要）

每个请求带 4 个请求头：

请求头内容
X-AdBrain-Site配置里的 site（不能为空，最长 128）
X-AdBrain-Time当前 Unix 时间戳（秒）。和店铺时钟相差超过 ±300 秒会被拒
X-AdBrain-Nonce每次请求新生成的随机串，16–64 位，只能用 A-Z a-z 0-9 _ -。600 秒内不能重复
X-AdBrain-Sign签名：64 位小写十六进制

签名 = HMAC-SHA256(secret, 签名原文)，十六进制小写。签名原文是 5 行，用 \n 连接：

请求方法大写            例：GET
路由                    例：/peptide/v1/adbrain/options
X-AdBrain-Time 的值     例：1795370000
X-AdBrain-Nonce 的值    例：k3J9xQ2mP0aZ7wLr
sha256(原始请求体) 的小写十六进制
  • 路由固定写 /peptide/v1/adbrain/...，不带域名、不带 /wp-json、不带查询参数。
  • 查询参数不参与签名（例如 pull 的 from/to），靠 Nonce 防重放。
  • GET 请求体为空，空串的 sha256 是 e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855。
  • POST 用 Content-Type: application/json，签名用的必须是实际发送的那串字节（先序列化，再签名，再原样发送）。

3. 错误格式

出错时统一返回：

{"ok": false, "code": "bad_sign", "message": "The signature is not valid."}
HTTPcode原因
503bridge_not_configured这家店没开启（总后台没生成密钥，或已关闭）
401bad_site缺 X-AdBrain-Site
401bad_time时间戳缺失或偏差超过 300 秒
401bad_nonceNonce 格式不对
401bad_sign签名不对（密钥、路由、请求体任一不一致）
401replayNonce 600 秒内用过
400见各接口参数不对
404creative_not_found素材编号不存在
409in_progress同一个幂等键的请求还在处理中，稍后重试
409creative_in_use要删的素材已有数据，且没传 if_in_use=archive
500issue_failed / relink_failed / delete_failed / archive_failed店铺内部错误，可重试

4. GEToptions — 读取素材选项

读取这家店的素材属性词表、可选落地页、时区和链接模板。建议在发号前先调一次。

GET {base_url}options

返回

{
  "ok": true,
  "store_timezone": "America/New_York",
  "home_url": "https://www.korgavex.com/",
  "url_template": "utm_source={{site_source_name}}&utm_medium=paid&utm_campaign={{campaign.id}}&utm_term={{adset.id}}&utm_content={{ad.id}}&placement={{placement}}&ad_name={{ad.name}}",
  "vocab": [
    {"attr": "hook", "value": "lab", "label": "检测报告", "required": true},
    {"attr": "fmt",  "value": "...", "label": "...", "required": true}
  ],
  "landing_pages": [
    {"url": "https://www.korgavex.com/", "label": "首页", "group": "..."}
  ]
}
字段说明
vocab素材属性可选值。必填属性：hook（卖点）、fmt（形式）、angle（角度）；可选：lang（语言）
landing_pages这家店允许的落地页。发号 / 换落地页只能用这里面的地址
url_templateMeta 广告「网址参数」的固定模板（发号返回的 tracking_url 已经带好）

5. POSTcreatives/issue — 新素材发编号

登记一个新素材，返回素材编号（如 C0123）、专属投放链接和建议的广告名。幂等：同一个 idempotency_key 重复提交，返回第一次的结果，不会重复发号（记住最近 500 条）。

POST {base_url}creatives/issue
Content-Type: application/json

{
  "idempotency_key": "adbrain-job-8812",
  "attrs": {"hook": "lab", "fmt": "video", "angle": "trust", "lang": "en"},
  "landing_url": "https://www.korgavex.com/",
  "lp_ver": "v2",
  "note": "Ad Brain 生成，批次 8812",
  "want_code": "C0500",
  "from_ad_id": "120211234567890123",
  "image_base64": "data:image/jpeg;base64,/9j/4AAQ...",
  "image_filename": "creative-8812.jpg"
}
参数必填说明
idempotency_key是1–128 个可见 ASCII 字符，Ad Brain 自己的任务号即可
attrs是对象。值按词表 value 匹配，也接受中文 label；都对不上或必填没给时，自动用词表里第一个值，并在 attr_notes 里注明
landing_url否必须是 landing_pages 里的地址；不在列表里会改用首页，warnings 里有 landing_url_not_allowed
lp_ver否落地页版本名，1–32 位，字母数字和 _ . -；会加进链接 &lp_ver=
note否备注
want_code否想要的编号（C + 4–9 位数字）；被占用会另发一个，warnings 里有 want_code_taken
from_ad_id否已经在跑的 Meta 广告编号（6–25 位数字），顺便归到这个新素材
image_base64否素材图片，jpg / png / gif / webp，解码后 ≤ 10 MB；可带 data:image/...;base64, 前缀。存不进去不影响发号
image_filename否图片文件名

返回

{
  "idempotent_replay": false,
  "ok": true,
  "code": "C0123",
  "tracking_url": "https://www.korgavex.com/?cr=C0123&utm_source={{site_source_name}}&...&lp_ver=v2",
  "suggested_ad_name": "C0123_hook-lab_fmt-video_angle-trust_lang-en",
  "landing_url": "https://www.korgavex.com/",
  "landing_label": "首页",
  "lp_ver": "v2",
  "attrs": {"hook": "lab", "fmt": "video", "angle": "trust", "lang": "en"},
  "attr_notes": [{"attr": "fmt", "given": "视频", "used": "video", "how": "label"}],
  "thumb_url": "https://www.korgavex.com/wp-content/uploads/...-150x150.jpg",
  "from_ad_id": "120211234567890123",
  "relinked": true,
  "warnings": []
}
  • tracking_url：整条复制到 Meta 广告的网址里即可。一个素材一条链接，投到多少广告都用同一条。
  • idempotent_replay: true 表示这是重复提交，返回的是第一次的结果。
  • attr_notes[].how：label = 按中文名匹配上；fallback = 没匹配上，用了第一个值。
  • warnings 可能有：landing_url_not_allowed、lp_ver_invalid、want_code_invalid、want_code_taken、from_ad_id_invalid、from_ad_relink_failed、image_not_saved。有警告也算发号成功。
  • 错误：bad_idempotency_key（400）、bad_attrs（400）、in_progress（409）、issue_failed（500）。

6. POSTcreatives/update-landing — 换落地页

修改某个素材的落地页和 / 或落地页版本。只改传了的字段。改完要把新的 tracking_url 重新填到 Meta 广告里。

POST {base_url}creatives/update-landing
{"code": "C0123", "landing_url": "https://www.korgavex.com/shop/", "lp_ver": "v3"}
参数说明
code必填，素材编号
landing_url可选；空串 = 改回首页；不在 landing_pages 里报 landing_url_not_allowed（400）
lp_ver可选；空串 = 去掉版本；格式不对报 lp_ver_invalid（400）
{"ok": true, "code": "C0123", "landing_url": "...", "landing_label": "...", "lp_ver": "v3", "tracking_url": "..."}

7. POSTcreatives/relink-ad — 广告归位

把一个 Meta 广告（通常是 pull 返回的 unregistered_ads 里的）归到某个素材，之后它的数据算在这个素材上。

POST {base_url}creatives/relink-ad
{"ad_id": "120211234567890123", "code": "C0123"}
{"ok": true, "ad_id": "120211234567890123", "code": "C0123"}

错误：bad_ad_id（400，必须是 6–25 位数字）、creative_not_found（404）、relink_failed（500）。

8. POSTcreatives/delete — 删除素材

删除一个素材，规则和店铺后台素材库的“删除”一样。

POST {base_url}creatives/delete
{"code": "C0123", "if_in_use": "archive"}
参数说明
code必填，素材编号，如 C0123（大小写不限）
if_in_use素材已有数据时怎么办：fail（默认，返回 409）或 archive（改为归档，数据保留）

“已有数据”= 有访客、有花费，或有广告用过这个素材。没有数据的素材直接删除，编号作废、不会再发给新素材（避免 Meta 里还挂着的旧链接算错）。

返回

情况HTTP返回
没有数据，已删除200{"ok":true,"code":"C0123","result":"deleted","code_retired":true}
有数据，if_in_use=archive200{"ok":true,"code":"C0123","result":"archived","in_use":true}（已是归档的也返回这个）
之前已删除过200{"ok":true,"code":"C0123","result":"already_deleted","code_retired":true}，可放心重试
有数据，if_in_use=fail 或没传409creative_in_use
编号不存在404creative_not_found
参数不对400bad_code、bad_if_in_use
店铺内部错误500delete_failed、archive_failed，可重试

归档的素材仍出现在 pull 的 creatives_catalog 里（status 为 archived），历史数据照常统计。

9. GETpull — 拉区间数据

按日期区间拉这家店的素材效果、全店漏斗、人群画像、每日明细和脱敏订单。

GET {base_url}pull?from=2026-11-01&to=2026-11-21&mode=last&tz=America/Los_Angeles
参数说明
from / toYYYY-MM-DD，按 tz（不传则按店铺时区），含首尾。默认最近 7 天（含今天），最多 62 天
tz可选，按哪个时区切日。IANA 时区名（America/Los_Angeles、UTC）或固定偏移（UTC-8、GMT+8、-08:00、UTC-07:30）。不传 = 店铺时区
mode归因方式：last（默认，下单前最后一次付费访问）或 first（第一次付费访问）

参数不对返回 400：bad_range、range_too_long、bad_mode、bad_timezone。记得查询参数不参与签名，签名路由仍是 /peptide/v1/adbrain/pull。

返回（顶层）

字段说明
store_timezone店铺自己的时区
applied_timezone这次实际切日用的时区（传了 tz 就是它，否则同 store_timezone）
from、to、mode实际使用的区间和归因方式
partialtrue = 某部分数据读取失败，结果可能不全
creatives_catalog全部已登记素材：code, status, attrs, note, thumb_url, landing_url, lp_ver, created_at
ads_map广告 → 素材：ad_id, code, ad_name, adset_id, campaign_id, first_seen_ms, last_seen_ms
unregistered_ads还没归到素材的广告：ad_id, code, ad_name, first_seen_ms, spend_cents 等，可用 relink-ad 归位
range_board区间汇总，见下

orders_ledger区间内订单（脱敏），最多 5000 张
orders_truncatedtrue = 超过 5000 张被截断，请缩小区间

range_board

字段说明
rows[]每个素材一行（见下表）
total广告带来的访客合计，结构同一行（code 为 *）
unattributed未归因的访客（没带素材参数进站的，包括自然流量和直接访问），漏斗字段同一行，code 为 UNATTRIBUTED；没有花费、展示、点击和 behavior；多一个 returning_from_ad = 以前从广告来过、这次没带参数回来的访客数（已算在 visitors 里）

  • 订单状态包括：processing、completed（已付）、pending、on-hold、failed、refunded、cancelled。
  • payment_status_norm 标准化付款状态：PAID（processing / completed）、REFUNDED（付过款后退款）、UNPAID_CHECKOUT（pending / on-hold）、FAILED、CANCELLED、其他为 OTHER。
  • failure_reason：gateway_reported_failure（支付通道回报失败）、order_marked_failed（订单标为失败但通道没回报）、payment_result_unknown（待付款且付款结果未知）；其他情况 null。
  • gateway_error_code 目前一直是 null：支付通道的回调只告诉失败，不给拒付原因或错误码。
  • payment_attempts 付款尝试次数；last_attempt_state 最近一次尝试的状态，没有为 null。

  • is_test_hint：邮箱或姓名含 test，或被标记为测试单。统计时建议排除。
  • attributed_*：按 mode 归因到的素材和广告；没有付费访问为空串。没付款的订单（待付、失败等）现在也会带归因。
  • 金额全部是分（整数）。

10. 签名示例代码

Python 3

import hashlib, hmac, json, secrets, time, urllib.request

def call(store, method, path, body=None, query=""):
    # store = 配置里的一项：{"site", "base_url", "secret"}；path 如 "options"、"creatives/issue"
    route = "/peptide/v1/adbrain/" + path
    raw = b"" if body is None else json.dumps(body, ensure_ascii=False, separators=(",", ":")).encode()
    ts, nonce = str(int(time.time())), secrets.token_urlsafe(18)
    canonical = "\n".join([method.upper(), route, ts, nonce, hashlib.sha256(raw).hexdigest()])
    sign = hmac.new(store["secret"].encode(), canonical.encode(), hashlib.sha256).hexdigest()
    req = urllib.request.Request(store["base_url"] + path + (("?" + query) if query else ""),
                                 data=raw if body is not None else None, method=method.upper())
    for k, v in {"X-AdBrain-Site": store["site"], "X-AdBrain-Time": ts,
                 "X-AdBrain-Nonce": nonce, "X-AdBrain-Sign": sign}.items():
        req.add_header(k, v)
    if body is not None:
        req.add_header("Content-Type", "application/json")
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.loads(r.read())

# call(store, "GET", "options")
# call(store, "POST", "creatives/issue", {"idempotency_key": "job-1", "attrs": {"hook": "lab"}})
# call(store, "GET", "pull", query="from=2026-11-01&to=2026-11-21&mode=last")

Node.js 18+

import crypto from "node:crypto";

export async function call(store, method, path, body, query = "") {
  const route = "/peptide/v1/adbrain/" + path;
  const raw = body === undefined ? "" : JSON.stringify(body);
  const ts = String(Math.floor(Date.now() / 1000));
  const nonce = crypto.randomBytes(18).toString("base64url");
  const canonical = [method.toUpperCase(), route, ts, nonce,
    crypto.createHash("sha256").update(raw).digest("hex")].join("\n");
  const sign = crypto.createHmac("sha256", store.secret).update(canonical).digest("hex");
  const res = await fetch(store.base_url + path + (query ? "?" + query : ""), {
    method, body: body === undefined ? undefined : raw,
    headers: { "X-AdBrain-Site": store.site, "X-AdBrain-Time": ts, "X-AdBrain-Nonce": nonce,
      "X-AdBrain-Sign": sign, ...(body === undefined ? {} : { "Content-Type": "application/json" }) },
  });
  return res.json();
}

11. 常见问题

一直返回 503 bridge_not_configured

这家店还没开启。请平台所有者在总后台「Ad Brain 接口」页点开启，再把新配置交过来。

一直返回 401 bad_sign

  • 密钥是不是这家店的、是不是最新的（重新生成过会失效）。
  • 签名用的路由是不是 /peptide/v1/adbrain/...（不能带域名、/wp-json、? 后面的参数）。
  • POST 签名用的请求体和实际发送的是不是同一串字节（不要签名后再重新序列化）。

401 bad_time

服务器时钟偏了，校准 NTP。

返回空白 404 或 HTML 页面

请求没到达接口（地址拼错或被网络层拦截）。确认地址是配置里的 base_url 加路径；仍不行请联系平台所有者。

pull 很慢或超时

区间越长越慢，订单多的店建议按周拉；客户端超时设到 120 秒。

数据口径

  • 日期默认按店铺时区（store_timezone）；传 tz 时按 applied_timezone。
  • 全店数字看 store_total；只看广告带来的看 total；两者之差就是 unattributed。
  • 花费只能对到素材，分不到落地页版本。
  • 访客、意向分层和店铺后台「广告数据追踪」看板同一套口径。
