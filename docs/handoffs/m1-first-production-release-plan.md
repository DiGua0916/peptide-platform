仍然要让所有者和素材会话知道的几点（不是拦它，是提醒）：

- **数据修复仍是随代码自动跑的**：代码上线后，后台任务会直接改生产数据库里的访客表。没有先出“会改多少行”的报告，也不保留原值。改成的值是确定的（最早一次访问），原值本来就是错的，所以风险不大；但这是一次直接写生产数据的动作，所有者在它那边确认上线时应当知道。建议上线前先在 6 家店各跑一句只读的计数，看会改多少行；上线后看 `pc_track_first_visit_fix_log` 里的行数对不对得上。
- **失败时会一直重试**：修复语句如果执行失败，不记“已跑过”的标记，下一个请求又会排一次任务，没有次数上限和间隔。正常情况下不会失败；万一某家店一直失败，会反复对访客表执行这条更新。上线后各店确认一次标记已写上即可。
