截至上述日期，已有记录覆盖以下范围；这些是历史证明摘要，本次未重跑，也不把本地环境结果当成正式生产环境证明。

- 原生 quickview／Buy now、已有购物车商品重复加购、新增加购及发起 checkout 已做本地真实操作核对，覆盖对应事件、身份关联与报表增量。
- 既有本地模拟付款/订单的 Data 关联有历史验证；这不等于真实支付提供商通知接入或验收。
- 真实新加坡公网访问及国家报表已有 PASS；这证明对应国家数据链路，不代表地图已能显示新加坡轮廓。
- 105阶段对既有启用来源进行六个报表 GET 与13项对账，结果 PASS；属于读取现有事实的对账，不是新客户完整旅程或所有组合测试。

PHP 8.3／WooCommerce 11.2 仅是2026-11-01已测试上下文，不是最低版本要求或任意版本兼容承诺。Store API 加购观察依赖内部成功钩子；升级 WooCommerce 时须按[追踪协议第6节](tracking-protocol.md#6-服务端事实前端不用也不应该上报)重新核对钩子和新/已有商品分支语义。

## 正式环境部署前提（由部署负责人配置）

1. 使用正式 WordPress origin 与 HTTPS；collector 保持既有同源 endpoint、协议和隐私门。历史临时本地 router、转发隧道及端口不是生产默认值。不要照搬本地数据库、账号、证书、路由或机器路径；通过正常部署流程配置正式环境。
2. 国家查询使用本地只读 MMDB，资源及机器相关 bootstrap 留在 Git 外。使用显式资源时，由操作方将 `PC_DATA_GEOIP_DATABASE` 配置为可读的绝对本地路径。若选用 DB-IP 署名，须使用精确的 `PC_DATA_GEOIP_ATTRIBUTION = 'db-ip'` 配置并保留现有署名展示；已有 Woo 管理的 GeoLite2 可作为只读 fallback。本文不新增资源、密钥、下载器或配置操作；具体约束见[国家资源说明](data-country-resource-v1.md)。
3. 可信服务器/代理须先将真实客户端地址规范化到 PHP `REMOTE_ADDR`，再进行国家查询。匿名请求自带的转发头不能直接信任；`PEPTIDE_CORE_TRUSTED_PROXIES` 是限流地址处理配置，不提供国家查询的真实地址规范化，也不能把其限流聚合键当成 MMDB 地址。
4. 国家地址只作瞬时本地查询，不记录或持久化原始 IP。没有可用资源、受信任地址或合格结果时，诚实保留 `unknown`／`unavailable`，不猜测国家。本地已通过的运行环境不能替代正式环境配置与验收。
5. 保留 GPC／退出采集／员工排除、权限、原 owner 关联、稳定 UID、重试与既有导出/抹除/保留期限规则；不因上线或对账绕过隐私门。

## 部署后按真实已发布业务页面核对

由获授权的负责人在正式环境另行安排，记录实际日期范围、店铺时区和域名筛选。只使用既有已发布业务页面与真实成功点：访问、曝光、商品查看、原生加购、发起结账，以及业务允许时已确认的订单事实。

对每个获准核对的来源，检查“实际来源 → 接收 ACK → 持久化 → 对应报表”的同一事实与增量，核对身份归属、去重、筛选及未观察状态。服务端加购/订单事实以原生成功回调为准；浏览器尝试、queued 或导航不等于付款。不得伪造事件、手动切换 paid、为验收新增入口，或由本次文档执行者发起付款。本交接不授权生产变更、客户操作或自动通知他人。
