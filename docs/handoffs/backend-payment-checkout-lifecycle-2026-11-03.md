## Storefront implementation and native isolation checks

The checkout-navigation and pending-order modules are integrated behind the storefront branch of the payment plugin, version 0.4.3. New normal checkout GET navigation detaches only this Woo session's pointers to its own existing hosted-payment order, preserving that order, its financial fences, cart and customer. Explicit order-pay remains the original payment continuation. POST/REST/AJAX do not detach: repeated payment submissions retain same-order deduplication. A session-bound nonce protects an explicit new-checkout link. If saving the optional pointer change fails, only this operation's still-missing pointers are restored in memory; no persistence success is claimed.

Discovery uses native account ownership or a bounded same-Woo-session order capability, never a public email/order-number lookup. Cart/checkout/account surfaces show a compact, non-blocking list and native order/payment links. Unknown or modified sessions do not expose a payable provider link. The discovery hook runs only after a saved session URL passes validation, and optional UI/session-observer failures cannot change the payment outcome. Private pages set no-store/no-referrer/noindex headers.
