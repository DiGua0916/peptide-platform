# 主线 11-17～11-19 改动的测试（F1，2026-11-19）

所有者要求测试：波多黎各地址、CDN 多账号令牌、换域名自检、支付绑定自愈、强制删除插件。
CAPI 隐身桥和去掉 Meta 两项所有者说不用 F1 管，不在测试范围；F1 不发布隐身桥。

## 测试版

本机分支 `claude/m1-test-1119`（未推送，不合回主线）= 主线 `b5ee1cf9`，另外三处只为沙盒测试：
去掉 `wp-capi-stealth-bridge` 目录；发布工具换回 `0d12c91b` 的版本（新版发布工具要求包里必须有桥接插件）；
关键链路样例 3 的波多黎各地址改成新入口 US/PR。沙盒发布 `t1119-4`（记录 #35）通过：关键链路 54 通过 / 0 失败。沙盒现在运行这个测试版。

## 结果

| 改动 | 结果 |
|---|---|
| 单元测试（新增 6 组） | 全部通过：前台无 Meta 291、服务端无 Meta 17、CDN 多账号 35、换域名自检 29、强制删除插件 28、支付绑定自愈 41 |
| 波多黎各地址 | **有问题。** 新入口 US/PR 正常：有运费、金额对得上；下单时 PR/* 和美国 + 006/007/009 邮编都改成 US/PR。但旧入口（国家 = PR）在购物车 / 结账阶段**选不到运费**：PR 已从可配送国家里去掉，而改写只在建单时做，算运费时还是 PR。关键链路原样例 3（国家 PR）两项失败就是这个。会碰到的人：保存过国家 PR 的老客（s0010 有 1 位）、浏览器里存了上次结账地址的回头客（结账回填）、带地址的恢复链接。生产上以国家 PR 下过单的有 38 单（s0001 2、s0007 16、s0008 11、s0010 9）。建议在更新顾客地址时也做同样的改写（Store API update-customer 和经典结账），再上线。 |
| 换域名自检 `wp pchq-domain verify all --offline` | 正常输出各项。沙盒报“CDN 域名表没有登记”，是沙盒本来没登记，符合预期。 |
| CDN 多账号令牌 | 总后台 CDN 页正常渲染，无报错。沙盒没有配置任何令牌，旧令牌自动迁移只由单元测试覆盖，沙盒里测不到。 |
| 支付绑定自愈 | 沙盒没有绑定记录，`audit()` 为空；关键链路的下单和支付正常。自愈本身只由单元测试覆盖。 |
| 强制删除插件 | 总后台插件页正常渲染，无报错；沙盒插件库为空，实际删除流程只由单元测试覆盖。 |
| PHP 错误日志 | 部署后没有新的 PHP 致命错误或警告。 |

## 主线现在发不了生产的原因（和测试结果无关）

1. 本机测试关卡有 2 组失败：`m7-pixels-pure`、`m7-purchase-dedupe-pure`。它们仍然要求服务端向 Facebook 发购买事件，和“去掉 Meta”冲突，要由改 Meta 的一方更新测试。
2. 版本号规则：`peptide-hq`、`peptide-panapay` 内容变了但版本号没抬。
3. 发布工具会把 `wp-capi-stealth-bridge` 发到并启用在 6 家店上。F1 不执行这一项。
