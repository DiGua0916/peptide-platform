# Native product creation-time metadata

054 adds an optional ordered `created_at` column to the product detail report. The 28 numeric `metrics`, their order, rate definitions, defaults10 and period/comparison calculations remain unchanged. The response adds `columns` (numeric metrics followed by creation metadata) and `report_timezone`. Clients that receive an older metrics-only response retain the existing column behavior.

Each parent `product` and child `variation` identity exposes `created_at` as UTC ISO8601 or null, and `created_at_label` as `Y-m-d H:i:s` in the store timezone returned by `wp_timezone()`. Both come from that native product object's `get_date_created()->getTimestamp()`. Variation dates use their own native object; absent/undated/deleted objects are null, with a UI dash and empty CSV cell. Existing cached parent reads and the existing variation read supply metadata; no new query or collection is introduced.

The chooser can select, move, persist and remove creation time. It never counts towards the minimum five numeric selections, and its checkbox stays enabled at that boundary. Existing empty, short or obsolete saved preferences retain their prior behavior. Creation time is rendered as one escaped cell, without current/previous/change or percentage units. Its header is deliberately not sortable; `sort=created_at` is rejected by the unchanged numeric sort whitelist. A caption identifies the display timezone and explains that CSV uses UTC.

The CSV columns whitelist accepts the numeric/metadata union. A requested `created_at` becomes one `created_at_utc` field at the selected position, for both parents and variations. Numeric-only exports preserve their original 11 base fields and exact bytes. Full matching rows, filters, pagination-independent iteration, selected order, formula escaping, unknown-column errors and stale/draft export guards remain shared with the existing path.
