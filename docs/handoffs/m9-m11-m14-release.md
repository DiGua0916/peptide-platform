**商品链接 302 跳首页，和 FE-02 的冲突**（11-14 所有者已定：302 + 弹窗不动，FE-02 先不开。下面是当时的分析，留作以后要做真正商品页时参考）

- 现在（主线、生产 s0010、沙盒都一样）：商品链接 `/product/<slug>/` 一律 302 到 `/?vc_product=<ID>#vc-products`，也就是首页 + 自动打开这件商品的弹窗。弹窗打不开时，顾客看到的就是首页。
- 打不开的一个已知原因已在这次修掉：页面在后台加载（在新标签页里打开广告链接、应用内浏览器预加载）时，线上代码直接放弃打开弹窗。别的原因（设备不支持弹窗入口、商品下架）仍然会落到首页。
- FE-02 做的是反方向：弹窗打开后把地址栏改成 `/product/<slug>/`，方便顾客复制分享；它依赖“这个地址会 302 回首页 + 弹窗”。所以两件事绑在一起：
  - 如果要改 302（例如 `/product/<slug>/` 改成真正的商品页，或者落地不再经过首页），FE-02 写进地址栏的地址、以及“打不开时显示什么”都要同一次一起改，否则分享出去的链接和顾客当时看到的不是同一个页面。
  - 反过来，FE-02 打开后每个分享链接都要多走一次 302（11-12 本机量过：经过 302 时弹窗打开 776 毫秒，直接打开落地页 490 毫秒，多约 0.3 秒；本机不限速，真机会更多）。
- 建议：先保持 302 + 弹窗（广告落地页的满减券、热销、运费、离开挽回都在弹窗里，已逐个验过）；FE-02 先不开，等所有者定了“商品链接要不要有真正的商品页”再一起做。商品页这一层（302 本身）是主线的入口代码，不在 F5 名下；FE-02 在 F5 名下。

**总的估计**（11-14 再更新）：模块代码 11-23 随 F1 日程上生产。开关按所有者定的顺序：发布时开 `pc_buyer_no_palette`、发布后开 `pc_trust_badges`（6 家店一起）；`pc_buyer_recognition` 和 `pc_front_speed` 沙盒验过后先在试点店 s0001 开（M11 观察一周），没问题再开其余 5 家；`pc_product_activity`、`pc_buyer_extras`、`pc_entry_address` 先关着。所有者那边已经没有待定的开关。

**库存短句怎么修的**

- 原因：WooCommerce 11.2.1 选中规格（`found_variation`）后，要等 `setTimeout` 300 毫秒才把这个规格的内容（包括库存句）画进页面，然后触发 `show_variation`。弹窗自己的刷新（选中规格的当下、表单有变化时）可能全落在这 300 毫秒之前，之后就没人再读，短句一直空着。本机复现：直接打开多规格商品落地页 3 次全空，手动让弹窗刷新一次就出来。
- 修法（`assets/product-dialog-meta.js`，+9 行）：在 WooCommerce 自己的 `show_variation`、`hide_variation`、`reset_data` 事件上再读一次。文案、样式、换规格时那 300 毫秒里先把旧数字藏起来的做法都没变；简单商品不受影响（不挂这几个事件）。
- 本机验证（SQLite 副本，应用内浏览器）：修之前直接打开 3 次全空；修之后直接打开 3 个多规格商品和商品链接共 6 次全部显示；在弹窗里依次换 3 个规格，换的那 300 毫秒里短句是隐藏的，之后显示新规格自己的库存（50 / 49 / 50）；关掉弹窗再开另一个商品正常，没有多余的短句。新用例 `product-dialog-meta.cjs`（8 项）在修之后的脚本上通过、在修之前的脚本上失败。44 个地址比对结果不变（这个文件只是脚本内容变了）。
- **沙盒里请 F1 验**（手机，6 家店任选一家有多规格商品的）：① 用广告链接 `/product/<多规格商品>/` 打开 5 次，每次弹窗里规格下面都有 “N in stock”；② 在弹窗里换规格，短句先消失一下再变成新规格的数字，不会停在旧数字上；③ 简单商品照常显示；④ 在新标签页里打开商品链接、过几秒再切过去看，短句也在。
