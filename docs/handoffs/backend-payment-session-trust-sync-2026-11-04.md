# Bind checkout trust to the authenticated HQ session

Author: Codex. Task files: `D:/Codex/Tasks/2026-11-04/payment-session-trust-sync`.

The owner explicitly requested a permanent fix after a new checkout was rejected with an old host list despite saving both account settings. On order 11744, HQ had created a session using its new frozen host policy, while the store froze an older 60-second METHODS cache and rejected that same URL. Clearing the transient synchronized later configuration but did not remove this race or repair the persisted attempt.

## Proposed and implemented boundary; verification pending

HQ's authenticated CREATE/STATUS response may add `checkout_policy: {version:1, reference:<original local reference>, payment_hosts:[...]}` to a created session. The policy is derived only from that HQ row's encrypted original host snapshot, including its original gateway hostname. It is not derived from today's account settings or from the returned URL. The existing nonce-bound response HMAC covers the entire envelope. Bridge validates the exact account, reference, policy shape, canonical host list and HTTPS/public cashier URL. Old HQ responses without this field retain their old validation behavior; malformed policy never grants trust.

The native Session Service binds that verified policy to the exact new attempt before its final URL validation and persists it. Existing central created sessions whose old snapshot rejects the saved URL can use the read-only STATUS path to obtain the policy of the same original session. Exact original URL/type, account/reference, native gateway/order fingerprint, unpaid state, persisted book and order lease are rechecked. The saved URL ciphertext and permanent creation reservation are preserved. No second CREATE, callback, payment completion, refund or stock action is added.

Selected runtime scope is four payment files: `peptide-panapay.php` (0.4.5), `includes/class-hub.php`, `includes/class-bridge.php`, and `includes/class-session-service.php`. Actual QA, source commit, publication receipts and remaining supplier 404 limitations will be added after verification. No production publication or order-policy recovery is claimed by this proposal.
