# 多店铺（投手店铺）方案 v1

2026-10-23 · Claude · 状态：方案，未开始实现

用户要求：后面有很多投手，每个投手要有自己的店铺，用积木各自装修。登录时只能进自己的店；所有店铺解析到同一台服务器，母版跟着店铺走（参照 Shopname）。

## 已确定（用户 2026-10-23 选择）

- **店铺完全独立**（和 Shopname 一样）：每个店有自己的商品、价格、库存、订单、顾客、装修和域名，互不相干。店主在总后台汇总查看。
- **投手能管的**：店铺装修（积木、页面、菜单、首页 SEO、域名）、营销活动（满减、优惠码、运费折扣）、查看自己店的数据（仪表盘、访客、订单，只读）、广告像素。
  - 商品、订单处理、支付、物流、税费、系统设置由店主（总管理员）负责。
- **先在新的本地站点试**，不动现在和 Codex 共用的 LocalWP 站点（订单 #54、退款 #55 等数据保留）。

## 架构：WordPress 多站点（Multisite，子域名模式）

| 要做到的 | 做法 |
|---|---|
| 同一个服务器 IP，按域名打开不同店铺 | WordPress 自带的“域名 → 站点”查找（`wp_blogs`）。每个店先有子域名 `<店铺>.<主域名>`，以后可以绑定自己的域名 |
| 每个店的数据互相隔离 | WooCommerce 和插件的表都按站点前缀分开（`wp_2_posts`、`wp_2_wc_orders`、`wp_2_pc_visitors`……）。插件建表一律用 `$wpdb->prefix`，现在就是按站点的 |
| 只能登录自己的店 | 用户表全网共用，但投手只被加到自己的店（角色“投手”）。进别的店后台会被拒绝；登录 Cookie 按域名分开 |
| 母版跟着店铺走 | 站点 1 是母版店。新开店时复制母版的装修（积木布局、模块、主题设置）、页面、菜单和插件设置，可以选择是否复制商品。之后各改各的 |
| 服务器 | 泛解析 `*.主域名` 指向服务器 IP。HTTPS 用 Caddy 按需签证书：签之前先问插件这个域名有没有登记，防止被滥用 |

## 分阶段

1. **本地多站点跑通**
   - 新建一个本地多站点（子域名模式），把现有站点的数据导入为母版店（站点 1）。
   - 插件网络启用；新站点创建时自动建表（`wp_initialize_site`）。
   - 检查主题、WooCommerce、区块结账、Store API 在子站点里都正常。
   - 逐项检查插件里的全站设置都是按站点存的，并补齐测试。
2. **开店与权限**
   - 总后台“店铺列表”：新建店铺（店名、子域名、投手账号、从母版复制、是否复制商品），可以进入任意店铺。
   - “投手”角色：菜单只显示装修、营销活动、数据、广告像素，订单只读。所有页面和保存动作都在服务端检查权限。
3. **广告像素**
   - 每个店填自己的 Meta / TikTok / Google 像素，前台输出浏览、加购、发起结账、下单事件，事件按 WooCommerce 数据生成。
   - 涉及向第三方发送访客数据：上线前需要用户确认顾客同意和隐私政策的处理方式（访客追踪的生产化目前是暂停的）。
4. **域名管理**（按 Shopname 的向导）
   - 流程：输入域名（默认同时绑 www）→ 显示要添加的 A 记录（服务器 IP）→ 验证 → 成功。
   - 列表：主域名切换（其他域名 301 跳到主域名）、HTTPS 状态、连接状态；解析连续 21 天异常且无访问时自动解绑。
   - CDN：先做独立 IP；以后需要时再接 Cloudflare for SaaS。
5. **总后台汇总**：各店的销售额、订单、访客一览，以及每个店的投手和域名。

## 对 Codex（主题）的影响

- 主题要在每个子站点独立工作：不写死站点地址、页面 ID、商品 ID；品牌、图片等设置按站点存（theme_mod / option 本来就是按站点的）。
- “复制母版”需要一份装修数据清单（哪些 option / theme_mod / 文章类型属于装修），需要和 Codex 对齐。
- 本地试验站点会同时链接主题目录，只读使用。

## 风险与待确认

- **支付**：每个店要单独配置收款。WooPayments 的政策禁止多肽（见 2026-10-23 讨论摘要），收款方式由用户决定。
- **邮件**：每个店的发件人、店铺实体地址要单独设置（营销邮件要求有地址），正式发信要有 SMTP。
- **WooCommerce 分析**等后台功能在多站点里按站点独立；总后台的汇总要我们自己做。
- **正式环境**：需要用户准备 Linux 服务器、泛解析和证书。本地测不了真实的域名解析和证书签发。
- **数据迁移**：现在的站点之后要整体迁到多站点的站点 1，迁移前要先备份。

## 需要用户做

在 LocalWP 新建一个多站点（子域名模式）的站点，步骤见当天的回复。Local 的管理员账号和密码由用户自己设置；之后我用 WP-CLI 操作，不需要密码。
