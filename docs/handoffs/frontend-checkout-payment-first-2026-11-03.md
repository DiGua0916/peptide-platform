# 结账页：先选支付方式

2026-11-03 · Codex → Claude

用户要先选择后台实际开通的付款方式。选银行卡后出现完整、正常的付款资料与账单地址；选 Apple Pay 时使用真正的 Apple Pay。用户已澄清：“就是正常的付款信息，国外是怎么填账单地址的，都要有”。手机优先，仍沿用 WooCommerce 原生 Checkout Blocks。

## 完整资料与交互

- **Card**：选择后展示支付方安全组件所需的持卡人姓名、卡号、有效期及安全码，以及完整账单信息。持卡人姓名与账单姓名按支付方要求映射，不假定二者永远相同。卡号/有效期/安全码必须由支付方托管字段或托管收银台采集；本站不自行创建明文收卡表单。
- **账单信息**：保留联系邮箱、账单姓名（first/last name）、国家/地区、街道地址、可选公寓/套房、城市、按国家适用的州/省和邮编；电话沿用店铺/网关实际要求。公司名若店铺已启用也保留，不强制新增。不能把美国 State/ZIP 必填规则硬套到所有国家。
- **地址复用**：默认允许“Use same address for billing”，可取消勾选后填写独立 Billing address。保留原生国家联动、必填校验、自动填充语义、错误提示及已填内容。收货地址继续用于配送，不能因选择某支付方式丢失。
- **Apple Pay**：选中真正支持的钱包方式后展开真实钱包按钮，客户明确点击按钮才调起支付方原生授权，不因切换 radio 自动弹授权。支付方如返回经钱包确认的 billing/shipping contact，按原生结账协议映射并校验；只补齐必要的缺失信息，避免重复填写整套卡资料。客户启动钱包后所需的商户验证会话不等同于订单/扣款，按支付方协议执行。前端授权动画不代表付款成功，支付结果仍由服务端确认。
- **最终动作**：选择方式和展开表单本身不创建订单、不创建支付会话、不扣款；完整校验后由客户明确确认付款。若现有通道只能在提交后进入支付方收银台，需在该方式说明里准确表达，不能宣称站内已支持安全卡组件。

## 前端处理

- 把原生 Payment Options 放在联系信息、收货地址之前，Express Payment 继续保持最前。修改原结账页的块顺序，让后台原生页面编辑器和前台顺序一致，不搬动 React 管理的 DOM。
- 选择器只呈现原生支付注册表中实际可用的方式，原 gateway ID 不变。不根据名称或展示图标推测渠道，不擅自开启商户或付款方式。
- 选中方式后，展开该网关自己的原生内容；卡输入、钱包授权继续由支付方实现。保留原联系/收货/账单/配送、附加字段、用途确认、金额和最终提交。
- 选择方式只改变选择，不创建订单、不发起支付。付款只能由客户明确执行最终动作。

## 当前真实接口的缺口

Panapay 目前是托管收银台：`has_fields=false`，Blocks 内容只有说明文字，提交原生订单后才创建托管会话并返回 iframe 或 redirect。当前前端公开 DTO 是 account_id、title、description、test_mode、supports、payment_icons。

Apple Pay 图标只是展示字段；没有官方钱包能力检测、Express Payment 注册或 Apple Pay 会话。不能把图标或后台名称当成已经开通的支付渠道。

本机检查时所有原生网关均 disabled/unavailable；前端不能在该状态下假装提供可付款的 Card/Apple Pay。真实正式站是否有可用账号，应由后端核对签名策略、授权及实际支付方能力。

## 后端需要提供的能力

1. **明确方式类型和实际流程**：在既有 HQ → 店铺签名策略和 Blocks 接口中提供支付方确认的 method_type（card/apple_pay/paypal/hosted 等）和 checkout_flow（hosted/hosted_fields/native_wallet 等）。这些是契约提案，字段名和版本需双方确认；不可从图标或标题推断。
2. **银行卡**：如需在本站选择后立即展示卡字段，须提供支付方支持的托管字段/SDK及令牌化流程；输入由支付方的安全组件接管，本站不新增明文卡号/CVV字段、存储或日志。若现有支付方只支持跳转收银台，就如实保留跳转流程，不能用假表单补外观。
3. **Apple Pay**：提供实际商户渠道、钱包会话和原生 Express Payment 集成；由 SDK 检查浏览器/设备资格，并完成所需 HTTPS/域名及商户验证。不支持的客户端隐藏该选项或提供正常替代方式。配置一个 Apple Pay 图标不满足此项。
4. **可用性同步**：只返回已启用、未归档、授权当前店铺、配置有效且适用于当前币种/国家/购物车的方式。地址或金额变化后重验；原选择不可用时明确告知并要求重选，不静默换渠道。
5. **保留原支付保护**：方式 ID、账号绑定、服务端校验、金额/币种权威来源、幂等、签名通知、在途冻结/归档兼容均保持。前端选择不创建会话；不在读取配置时自动下单或扣款。
6. **版本兼容**：当前 Bridge 对 DTO 白名单/字段结构严格校验，扩展须协调版本及 HQ → 店铺升级顺序。前端只消费公开能力，不接收密钥或完整商户配置。

## 验收

- 后台开/关/归档后，前端实际方法列表一致；不可用或读取失败时不展示假付款选项。
- Card 与 Apple Pay 各自走真实通道；切换不会重复提交，也不会创建订单。选择 Card 展开的是支付方组件，不是本站明文收卡表单。
- 真正支持的设备可调起 Apple Pay；不支持的设备不会看到可点击但无法工作的假钱包按钮。
- 配送/账单地址、币种、购物车变更后资格和金额重新核验，原生字段校验及确认项不被绕过。
- 支付方要求的 3DS/SCA 挑战、钱包取消/失败与重试按真实测试通道验收；保留必要地址及选择，不重复建单或扣款，不将取消误报为成功。
- 390/430px 手机操作、键盘焦点、错误恢复、不丢已填信息。真实支付及通知由用户或受控支付方测试执行；前端页面重排不等于真实通道验收。

## 本轮实际完成与限制

- 已发布本机原生结账页 8：Express Payment 保留首位，Payment Options 紧随其后，位于联系/收货/账单信息之前。全部 12 个原生子块的内容和属性保持，仅改变顺序；最终提交、附加字段与原生确认项保留。
- 已在真实桌面结账页及正式同源 390×844 手机预览验证顺序，未用 CSS 视觉排序或移动 React 管理的 DOM。Woo 原生页面编辑器和前台使用同一保存内容；当前自定义装修编辑器没有 checkout 文档，此次没有新增假积木。
- 手机实测取消“Use same address for billing”后出现独立账单字段：国家（251 选项含提示）、姓名、地址一/二、城市、州、邮编、电话；恢复勾选后独立表单收起，无横向溢出。只临时切换该复选框，未填写客户资料、改购物车数量或提交订单。
- 当前本机所有网关均 disabled/unavailable；因此已验证的是支付区排序与完整地址表单，不是选卡后安全收卡、Apple Pay 授权或成功付款。未擅自启用渠道，也没有修改后端插件源码。
- 银行卡安全组件及真正 Apple Pay 尚待后端提供上述能力。此文档中的新增 DTO 字段均为提案，不是已经生效的接口合同。
