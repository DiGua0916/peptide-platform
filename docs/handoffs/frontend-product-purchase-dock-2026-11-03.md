# Product purchase dock and compact metadata

2026-11-03 · Codex · PRODUCT-PURCHASE-DOCK

The user asked for one bottom purchase area containing quantity, Add to bag and Buy now, an obvious red discount from the selected product's real price, and a confirmed Add that finishes its small button firework before closing the product so browsing can continue. Buy now must retain the existing checkout action. Follow-up requests moved Clear, availability, SKU and Explore product details directly below the image, removed the empty space after specification options, and removed the title eyebrow and Offer details while keeping real campaign tiers compact.

## Native purchasing remains authoritative

`assets/product-purchase-dock.js` presents the original quantity container, Add button and Buy button. Variable products reuse the actual `.woocommerce-variation-add-to-cart` element inside its original `.single_variation_wrap` and original `form.cart`; simple products get one dock inside that same real form. Existing handlers, input names/values, variation ID, min/max/step, disabled/busy behavior and native form ownership are preserved. There is no proxy purchase button, cloned form, duplicate cart API or replacement checkout implementation. Teardown uses saved placeholders to restore original ancestry/order. The existing `stickyPurchaseEnabled` setting remains the enable boundary and native purchasing is untouched if it is disabled or required elements are missing.

Price, comparison price and discount text are copied from the actual server-rendered selected price nodes. The theme does not calculate a discount, parse money or invent an original price. Missing/cleared pricing and a selection without a sale hide the corresponding presentation. The dock reserves its measured height through a coalesced ResizeObserver/requestAnimationFrame path, accounts for the bottom safe area, and removes its reservation/listeners on teardown. It uses the existing ink/teal/white palette, equal-size Add/Buy controls and a red actual-discount label; reduced motion disables the presentation transition.

`assets/product-purchase-return.js` only owns the short confirmed-Add presentation. The existing backend/native quick-view code still validates HTTP 201, the real cart shape and matching purchased item, then emits its established cart and `added_to_cart` events. The theme additionally requires the current pending operation, matching opener, connected/current product dialog, explicit non-stale showcase mutation and actual cart items/totals before confirming feedback and scheduling return. An unrelated event, failure, unconfirmed payload or stale concurrent mutation cannot make the product close.

The feedback controller exposes a copy of the operation's active presentation configuration. Return waits for that actual enabled firework snapshot: default 850ms, bounded to the existing renderer's 600–1000ms lifetime. Disabled/missing/burst-disabled feedback and reduced motion do not gain an effect or forced wait; the close remains asynchronous so native success paint finishes first. It invokes the existing Close control and history cleanup, using the original dialog Close when no toolbar Close exists, and never redirects checkout itself. Buy retains its native checkout handler and cancels an earlier Add return. New pointer interaction, form/selection changes, Back/Escape/Close, a new confirmed cart mutation, hidden/pagehide state, opener/product replacement, abort and disposal invalidate old timers. Duplicate success and queued old callbacks cannot close a newer session.

## Metadata and campaign layout

`assets/product-dialog-meta.js` moves the actual Clear link, SKU line and Explore link into a compact strip before variations, directly after the product image in the mobile flow. Their original selectors and handlers remain reachable inside the same summary/form. Selected-specification text and availability are presentation copies of current native content; the original stock element stays in place for Woo. Pending/cleared variations or a still-mounted preceding stock template are not presented as current stock. Variable-product SKU presentation is hidden when the selected-specification line is hidden, including Clear/pending selection. The redundant specification/stock presentation is hidden only while the strip is mounted, and teardown restores moved native nodes.

`assets/product-dialog-interaction.css` sets the image-to-strip gap, removes form/summary whitespace, keeps Clear/Explore hit targets at least 44px, and styles the fixed native purchase area without a translated ancestor rebasing it during entry. The product-title eyebrow is visually hidden. `product-dialog-experience.js` removes the Offer details disclosure and presents the real active campaign tiers as compact threshold/reward pairs. Whole-dollar `.00` suffixes are shortened for those labels only; pricing, campaign calculations, app switches and final cart/checkout savings remain native.
