# M3 系列与商品目录 — 交接（F3，2026-11-10）

需求：HQ-05、HQ-06、FE-07、NF-12。分支 `claude/m3-series-361018`（M3 和 M10 在同一个分支上）。接口细节在 `docs/CONTRACT.md` 的“M3 系列与商品目录”一节。

## 做了什么

- **系列数据结构**（`hq/class-series-db.php`，版本选项 `pchq_m3_db`）：建 `pchq_series`、`pchq_series_products`、`pchq_series_campaigns`；给 `pchq_sites` 加 `series_id`、`buyer_name`、`onboarding_state`、`series_sync`。升级时建“系列 1”（`series-1`），把没有系列的店全部归入。可以重复执行；手工改过归属的店不会被改回去。
- **系列**（`hq/class-series.php`）：新建、改名、选母版店、四个版本号（商品 / 模板 / 活动 / 运费）、店铺归属、投手、开店预留系列、运费两档配置。
- **推送**（`hq/class-series-push.php`）：按版本号只发落后的部分；失败按 1 / 5 / 30 分钟重试，每 10 分钟巡检后补齐；店铺程序太旧时不报错、稍后再试；巡检项 `series_out_of_sync`。
- **主商品库**（`hq/class-series-catalog.php`）：从母版店导入（商品、运费、活动可分别勾选），整体替换，内容没变不加版本；在总后台直接改价格、把商品移出 / 放回系列；差异报告和确认记录。
- **系列管理页**（`hq/admin/class-series-page.php`，菜单“系列管理”）：系列、店铺（投手、换系列、差异报告、确认并开启同步、关闭同步、立即同步、恢复到同步前）、主商品库、运费两档、活动一览、差异报告详情。
- **店铺端**（`core/class-series-sync.php`）：`peptide_core_series` 选项；新订单写 `_pc_series_id`；`/hq/series/sync`（商品、运费、活动三部分，各带版本号，重复调用结果不变，`dry_run` 只出差异）；系列管理的商品在店铺后台只读；同步前自动存快照（留最近 3 份），`/hq/series/restore` 和 `wp peptide series restore` 恢复；`/hq/catalog-export` 母版店导出；命令行 `wp peptide series status|restore|export|diff`。
- **模板按系列下发**（改 `hq/class-design-push.php`）：每个系列自己的模板工作室、自动下发开关和下发任务；默认系列沿用原来的选项名，只有一个系列时行为和以前一样。日常会话的模板库页面没有改。
- **店铺复制**（改 `hq/class-store-clone.php`）：只允许在同一个系列的店之间复制；复制后重新把系列信息发给目标店。
- **工具**：`tools/catalog/series_diff_report.py`（把各店的差异报告汇总成 Markdown）、`tools/catalog/README.md`。
- **共用文件**：`hq/class-plugin.php`、`core/class-plugin.php` 各追加一行；`tests/data-observations-suites.json` 末尾追加 3 条。

## 几个要知道的设计决定

1. **母版店**：商品的描述、图片、规格在母版店里改，改完在系列管理里“导入”；价格可以直接在总后台改。总后台改的价格也会发回母版店（母版店只接收价格，不新建、不下架、不锁定），所以再次导入不会把价格改回去。
2. **现有店默认不同步**。每家店第一次同步前必须先“生成差异报告”，平台所有者看过点“确认并开启同步”才会改店铺的商品。报告必须是针对当前商品版本的。新注册的店默认接受同步（运费、活动直接下发），商品仍然要确认一次。
3. **同步后的店铺**：系列里的商品带“系列管理”标记，店铺后台改不了（包括从总后台一键登录进去的管理员）；系列里没有的商品改成草稿，不删除。只读是靠拦住“改商品”的入口实现的（编辑页保存和删除、快速编辑、批量编辑、款式增删改、WooCommerce REST），没有动权限，所以评价、专辑、批次 COA 照常能用。
4. **图片**：按内容哈希去重，复制出来的店里已有的同名同内容文件直接复用；只从母版店域名下载。某张图片下载失败不拦价格和其他内容，原因会显示在系列管理的店铺行里。
5. **改一个系列的价格只影响这个系列**：版本号、推送队列、落后判断都按系列算（测试 `m3-series-catalog-pure.php` 覆盖）。

## 待平台所有者确认

1. **运费两档的门槛**：PRD 写“不满 $1000 一律 $45”，所以默认值是不满 $1000 收 $45、满 $1000 收 $15。系列页可以改；保存之前不会下发任何运费。
2. **六家店的投手**：升级不会自动填投手姓名（仓库是公开的，不写真实姓名），需要在系列管理里逐店填一次。PRD 里“光辉”对应 s0008 还是 s0011 也要在这时核对。
3. **商品内容的编辑方式**：现在是“母版店里改内容 + 总后台改价格”。如果希望总后台也能改描述和图片，需要另做商品编辑页。

## 已知限制

- 只读保护拦的是 WooCommerce 自带的改商品入口。peptide-core 里别的模块如果有自己改商品的入口（批量导入、自定义接口），需要先问 `Series_Sync::is_locked()`；命令行脚本不受限制。
- 总后台页面上发起的导入、差异报告、恢复都在一次浏览器请求里等店铺回应（超时 80 秒）。母版店第一次导出要给所有图片算校验码，可能超时，再点一次即可；商品特别多时需要改成后台任务。
- 差异比较不看商品的 SKU 和款式顺序，只看内容、价格、排序、图片、规格。
- COA 批次和报告不随系列同步，仍用“店铺复制 → COA 报告”。
- 商品属性一律按“自定义属性”同步；库存只同步有货 / 无货，不同步数量。
- 快照里商品状态只分“已发布 / 草稿”，恢复后原来“私密”“待审”的商品会变成草稿。
- “模板库”页面当前操作的是哪个系列，靠页面顶部的一条提示和店铺列表来区分；如果总后台的样式把系统提示隐藏了，需要日常会话在页面标题处显示 `Design_Push::current_series()`。
