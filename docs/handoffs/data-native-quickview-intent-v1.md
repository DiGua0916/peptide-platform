# Observed native quick-view opening

060 adds a passive source for the existing056 `product_intent` protocol. Its fact is **a matching native quick-view modal observed open and visible**, kind `quick_view_open`, result `completed`. This is not a Shopname hidden intent score, human-attention proof, purchase or buy-now outcome. Favorite, share and buy-now sources are not inferred.

The native implementation already exists in plugin `assets/showcase-quick-view.js` and `includes/modules/class-showcase-quick-view.php`. It moves its native product body into the reused `dialog.vc-showcase-quick` and dispatches a non-bubbling `vc:showcase-quick-state` before `showModal()`, followed by false when closing or showing fails. 090 preserves the exact `.vc-showcase` target when present and extends this passive state signal to the exact native opener when no showcase root exists, covering native merchandising/waterfall anchors. The native product-body PHP is unchanged. No quick-view control, template, endpoint, setting, cart or navigation behavior changes here.

The inert `window.VialCoveVisitorIntent.observe(document, callback)` module requires an original opener click with `isTrusted === true` and captures its native dispatch turn and the non-bubbling state event. It reads only the native parent-ID attributes. One strict resolver accepts an A or BUTTON bearing `data-vc-quick-open`, including clicks on nested label content; attributed SPANs and other unsupported elements are rejected. The source is its exact closest `.vc-showcase`, or the exact opener itself when outside a showcase. The reused native dialog/body/direct product child must match that parent. The original trusted click Event must still have a nonzero dispatch phase, with the same exact resolved opener/source, when matching native state is accepted. The native CustomEvent itself is deliberately not trust-gated. State alone or a state from a different opener/container cannot establish a successful opening. One bounded requestAnimationFrame check then requires connected nodes, `dialog.open`, visible document, positive modal/body/product geometry, CSS visibility and positive clipped intersection with the viewport. Close, show failure, source/dialog/product removal, a new source, suspend, pagehide or stop cancels an incomplete episode. A zero-delay task retires unused opener eligibility; replacement, consumption, suspend and stop clear that task. Phase zero rejects late state even before the task fires, so this is not an arbitrary millisecond acceptance window. A Promise microtask must not clear eligibility because native input can checkpoint microtasks between capture and bubble callbacks. No polling/interval or indefinite retry loop is used.

An initially hidden document may make one further eligibility check when it becomes visible, only while the same opening is still live. Repeated true events share one opening episode; actual close/reopen gets a fresh UID. BFCache restoration does not infer a new opening. Mutation checks observe only an active incomplete episode and cancel removal even if a target was reattached. After a qualifying observation, mutation watching stops and the one episode retains only deduplication state.

The immutable facts contain only:

```json
{"version":1,"product_id":101,"variation_id":0,"kind":"quick_view_open","result":"completed","event_id":"intent-<opaque UUID>"}
```

The collector starts the helper only for exact integer `productActionsProtocol ===1` and an available module. Its callback delegates to the existing `pushProductAction('product_intent', facts)`. 069 pairs an accepted quick_view_open intent with one ordinary parent product_view on the original current page; it adds no page_view. 090 leaves that collector, paired capacity checks, UID tombstones, ACK/retry and cleanup byte-identical. UID is generated once on the qualifying send; retries preserve the entire existing records. The module has no fetch/endpoint, cookies, storage, public generic emitter, form contents, product name, URL/path, recipient or business operation. It never uses `vc:cart-updated` to infer add/buy mode.

The theme advertises and enqueues the optional asset only when the exact existing Product_Actions helper capability is available. The helper is an observer dependency before startup.
