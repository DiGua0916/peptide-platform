# Observed native quick-view opening

060 adds a passive source for the existing056 `product_intent` protocol. Its fact is **a matching native quick-view modal observed open and visible**, kind `quick_view_open`, result `completed`. This is not a Shopname hidden intent score, human-attention proof, purchase or buy-now outcome. Favorite, share and buy-now sources are not inferred.

The native showcase implementation already exists in plugin `assets/showcase-quick-view.js` and `includes/modules/class-showcase-quick-view.php`. Both remain byte-identical to41a679a. That implementation moves its native product body into the reused `dialog.vc-showcase-quick`, dispatches a non-bubbling `vc:showcase-quick-state` on its exact `.vc-showcase` root before `showModal()`, and emits false when closing or showing fails. No quick-view control, template, endpoint, setting or business behavior changes here.

The new inert `window.VialCoveVisitorIntent.observe(document, callback)` module requires an original opener click with `isTrusted === true` and captures its native dispatch turn and the non-bubbling root state event. It reads only the native parent-ID attributes. The opener must be a native button in the same root, and the reused native dialog/body/direct product child must match that parent. The original trusted click Event must still have a nonzero dispatch phase, with the same exact opener/root, when the state is accepted. The native CustomEvent itself is deliberately not trust-gated. A root state event alone cannot establish a successful opening. One bounded requestAnimationFrame check then requires connected nodes, `dialog.open`, visible document, positive modal/body/product geometry, CSS visibility and positive clipped intersection with the viewport. Close, show failure, root/dialog/product removal, a new root, suspend, pagehide or stop cancels an incomplete episode. A zero-delay task retires unused opener eligibility; replacement, consumption, suspend and stop clear that task. Phase zero rejects late state even before the task fires, so this is not an arbitrary millisecond acceptance window. A Promise microtask must not clear eligibility because native input can checkpoint microtasks between capture and bubble callbacks. No polling/interval or indefinite retry loop is used.

An initially hidden document may make one further eligibility check when it becomes visible, only while the same opening is still live. Repeated true events share one opening episode; actual close/reopen gets a fresh UID. BFCache restoration does not infer a new opening. Mutation checks observe only an active incomplete episode and cancel removal even if a target was reattached. After a qualifying observation, mutation watching stops and the one episode retains only deduplication state.

The immutable facts contain only:

```json
{"version":1,"product_id":101,"variation_id":0,"kind":"quick_view_open","result":"completed","event_id":"intent-<opaque UUID>"}
```

The collector starts the helper only for exact integer `productActionsProtocol ===1` and an available module. UID is generated once on the qualifying send; retries preserve the entire existing record. The module has no fetch/endpoint, cookies, storage, public generic emitter, form contents, product name, URL/path, recipient or business operation. It never uses `vc:cart-updated` to infer add/buy mode.
