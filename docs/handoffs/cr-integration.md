## MySQL 实测（2026-11-11 晚）

为验证 SQLite 沙盒里验证不了的访问分段，单独下载了 MySQL 8.4.9（macOS ARM，dev.mysql.com）和带 `mysqli` 的 PHP 8.3.32（static-php-cli bulk，dl.static-php.dev；项目自带的 `tools/php` 没有 `mysqli`），都只放在会话临时目录。MySQL 跑在 127.0.0.1:3317，从零装了店铺（8811）和总后台（8812），标准 `wpdb` 驱动，店铺按生产方式注册到总后台。

- **访问分段正确**：真实浏览器带广告参数进站、停留约 1 分钟、再点站内页面 → 1 次访问、64 秒、2 个页面、4 个心跳都在里面（SQLite 下变成了 5 次访问）。`last_ms` 正常。
- **换广告规则正确**：换另一条广告 → 新访问；回到第一条广告 → 新访问；同一条广告再点 → 留在同一次访问。访客 `first_visit_id` 不变、`last_paid_visit_id` 跟着最新付费访问；`pc_ad_ads.last_seen_ms` 正确推进（SQLite 下这里是错的）；名字里没有编号的广告登记为未登记。
- **素材链路**：补登记归位、中文表头 CSV 导入、每日花费推送、每日上报（HTTP 200）、总后台按属性对比，数字一致。
- **订单上报**：付款订单上报总后台、总后台回查对账一致。
- 三个素材页面渲染正常；两边日志没有 PHP 致命错误、警告，也没有数据库错误。
- 结论：线 1 交接里“`GREATEST()` 在 SQLite 上算错”的问题确认只在 SQLite 插件上出现，MySQL 上一切正常，不需要改代码。
