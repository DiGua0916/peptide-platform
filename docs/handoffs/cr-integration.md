## 像素自动检查（2026-11-12）

- `Pixels\Health`：不额外发请求，读发送记录 `pc_px_log` 里最近 24 小时这个 Facebook 像素的真实回传结果，自动判断：
  - bad：最近一次失败且之后没成功过（令牌 / 像素 ID 类错误失败一次就报，其他错误连续 2 次）；
  - warn：成功率 < 90%（至少 20 条），或这个像素填好之后有广告访客进站、24 小时却一条事件都没发出；
  - idle：没有事件也没有广告访客；ok：回传正常（显示条数和成功率）。
  - Facebook 错误归类成投手看得懂的原因：令牌失效（190 等）、像素 ID 不对 / 没权限、连不上 Facebook、限流、其他。
- 广告设置页：正常时像素折叠成一行“回传正常：最近 24 小时 N 条，成功 X%”；出问题时页面顶部红 / 黄提示，像素卡片展开。投手首页同样提示（正常时不显示），“去处理”跳到像素卡片。

- 测试：cr-board-pure 加建议和排序检查（183 项）。沙盒 150 访客数据下各维度渲染正常。

## 看板三块新视图（2026-11-13）

按用户确认的方案，素材看板从上到下依次是：

1. **今天要做的事**（只在素材 / 广告 / 广告组维度显示）：把“建议停”“加投”的行变成一句动作（停掉 X / 给 X 加预算），配一句原因 —— `Board::reason()` 按漏斗里丢人最多的一步给话术（没意向 = 素材吸引来的人不对；没加购 = 看商品页价格库存；没进结账 = 看运费起订；没付款 = 看支付方式）。下面“再等等”列出观察中和样本不足的行，写明还差几个有效访客。
2. **花费与回报象限图**：横轴花费、纵轴 ROAS，圆大小 = 订单数，空心 = 还没出单；两条虚线是设置里的加投 / 止损阈值，上下各一块底色。至少两行有花费才显示。
3. **原来的素材卡片**（关键数字 + 漏斗 + 全部指标 + 访客名单），标题带维度名和条数。
4. **钩子 × 卖点热力格**（只在“按素材属性”）：`Board::attr_keys()` 额外产出 `mx:钩子|卖点` 组合行，`Board::split_matrix()` 把它们从属性行里分出来；格子按 ROAS 上色，灰格 = 还没试过的组合，可以当下一批拍摄方向。

测试：cr-board-pure 190 项（新增组合行、原因话术各项）。沙盒 150 访客数据下三块都渲染正确，日志无错误。

## 单条素材的人群画像和分析（2026-11-13）

店主要求：分析一条素材带来的整群人（不是单个客户），例如这条素材有多少苹果、多少安卓，他们的共同点和不同点；分析部分用总后台接入的 AI。

- **数据**（`Creatives\Audience`，纯函数）：`Board::aggregate()` 按素材累计归因那次访问的 15 个维度——系统、机型（地区代码合并）、浏览器（FB / IG 内置、Safari、Chrome…）、省 / 州、机型档次（高端 / 中端 / 入门 / 电脑，只是消费能力线索）、系统版本、设备类型、屏幕、国家、城市、ISP、IP 类型、语言、时区、版位。每个取值：人数、占比、中高意向、加购、结账、下单人数、订单、销售额、客单价、平均停留、人均页数、滚到 75% 以上的比例。另外算一份 `*` = 全部素材（“平均”）。结果在 `aggregate()['profiles']`。
- **规则分析**（`Audience::analyse()`）：同类型（占比过半）、不同项（和平均差 ≥ 10 个百分点）、来的是什么人、质量、谁在买谁不买（按系统 / 机型档次 / 浏览器拆，≥ 30 人才比较）、卡在哪（加购 / 进结账 / 付款，哪步相对掉得最多）、建议（加投 / 先查再投 / 减投 / 做同款，写明在 Meta 后台怎么操作）。每条带依据数字。付费访客 < 100 只给数据不下结论；不同维度完全重合的人群只说一次。
- **看板**：按单个素材时，卡片展开后在全部指标下面显示“人群画像”（前 4 个维度直接显示，其余收在“更多维度”）和“人群分析”，再下面是“AI 深度分析”。
- **AI**：卡片按钮 → `POST peptide/v1/creatives/audience-ai`（`Creatives\Audience_Ai`，投手可用）→ 按看板当前日期 / 归因 / 版本重算这条素材的画像，连同平均和规则结论交给总后台 `/ai/analyse`，用途 `creative`。只发汇总数字，不发 IP、姓名、联系方式。每条素材保存最近一次结果（`pc_cr_audience_ai`），同样条件 30 分钟内再点用上次的。
- **总后台**：`Ai::USES` 加 `creative => 素材人群分析`；AI 设置页多一块“素材人群分析人设”和店铺表两列。还没导入这个人设时借用全站分析师人设；不管用哪个人设都追加 `Ai::CREATIVE_TASK`（固定 5 段输出 + 可信度）。
- **数据包**：每套数据多 `profiles`（每条素材各维度前 8 项 + 规则结论）；CSV 多 `profile:素材编号:维度` 行。
- **滚动深度**：`visit_features()` 记 `scroll_depth`（这次访问最深百分比），`Board::behavior()` 汇总停留、页数、最深滚动。
- **部署**：店铺和总后台都要更新（总后台改了 AI 设置）。不需要改表。
- **测试**：`cr-audience-pure`（54 项）、`peptide-hq/tests/cr-hq-ai-creative-pure`（12 项，HTTP 用替身，不请求 AI）、`cr-board-pure`（199 项，导出加 profiles）。
