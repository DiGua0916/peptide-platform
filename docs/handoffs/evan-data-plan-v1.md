## 3. 方案

### 3.1 菜单与页面

- 新的顶层菜单 **“数据”**（slug `pc-data`），放在“营销活动”下面，子菜单和 Shopname 一一对应：实时数据、运营数据、商品详情数据、页面访问统计、页面商品转化、应用统计、落地页转化、转化率详情、邮件详情数据。**A/B 测试分析不做**（我们没有落地页 A/B 功能）。
- 现有的“分析”（WooCommerce 分析）和“访客”菜单先保持不动。上线后是否合并，再问 DiGua。
- 页面写法和 `pc-overview` 一致：PHP 输出外壳，`assets/data-*.js` 调 REST 接口渲染，图表沿用仪表盘现有的画法，不引入新库。

### 3.2 口径（和仪表盘一致）

- 时区：店铺时区 America/Los_Angeles。
- 销售额、订单数、客单价：已付款订单，减退款；**排除测试订单**（`Overview::is_test_order`）。
- 访客相关：只来自访客追踪；追踪关闭或没有数据时显示 0，并在页面上说明。
- 对比时间段：默认是紧挨着的上一个同长度时间段，可以自己选；同比 = (本期 − 对比期) / 对比期，对比期为 0 时显示“-”。
- 跳出率：只有 1 个页面的访问 / 落地页为该页面的访问。平均访问时长：访问的最后时间 − 开始时间的平均值。

### 3.3 接口

- `GET /peptide/v1/data/{realtime|operations|products|pages|page-conversion|apps|landing|conversion|emails}`，参数 `from`、`to`、`compare_from`、`compare_to`，以及各页面自己的筛选、排序、分页。权限 `manage_woocommerce`。
- 导出：同一接口加 `format=csv`。
- 新接口先写进本交接，确认后再进 CONTRACT（只给后台用，主题不调用）。

### 3.4 性能

先在打开页面时直接查原始表（和仪表盘一样），给常用查询补索引。数据量变大以后，再加按天汇总表，由 Action Scheduler 每小时生成一次。

## 5. 开工前要解决的问题

1. **归属**：`wp-content/plugins/peptide-core` 归后端 Claude。按 docs/COLLABORATION.md，协作者要改它，需要先在 Issue 或 PR 里说明，DiGua 同意后再改。
2. **前台代码没进仓库**：开发站点实际加载的主题脚本有 `visitor-tracking.js`、`visitor-adapter.js`、`visitor-video.js`、`carousel.js`、`navigation.js`、`experience.js`、`cart-drawer.js`、`modules-shared.js`、`modules-carousel.js`，这些都不在 GitHub 的任何分支里（仓库的主题只有 `site.js`）。P3 和端到端测试需要先把它们推上来。
3. **测试环境**：协作者电脑上没有 WordPress。vialcovepeptidescom.local 是 DiGua 电脑上的共用站点，协作者改的插件代码放不上去。要么协作者自己搭 LocalWP，再拿一份去掉客户信息的数据库；要么由 DiGua 拉分支后在共用站点验证。
4. **隐私**：访客追踪现在是测试模式，没有同意提示和保存期限，不能对真实顾客开启。“数据”板块的访客类指标在这之前只能看测试数据。P2 里新增的国家和来源也属于这类数据。
5. **站点语言**：开发站点的“站点语言”目前是简体中文，前台也跟着变成中文。原来的约定是前台英文、后台按个人设置用中文。需要 DiGua 确认是谁改的、要不要改回。
