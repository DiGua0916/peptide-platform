# 前后端契约草案

状态：讨论稿；尚未发布接口，也没有可调用的端点。

## 共同原则

- WordPress 为应用底座，主题负责展示，项目插件负责业务。
- 优先复用现有能力；确认 WooCommerce 后再决定产品和订单的具体数据来源。
- 双方先对齐字段、空值、权限和错误状态，再分别实现。
- 接口版本、路由、分页和认证方式在首个实现任务前确认。
- 面向浏览器的接口不包含数据库口令、管理员凭据和服务端密钥。

## 建议讨论的数据对象

| 对象 | 待讨论字段 | 尚待确定 |
| --- | --- | --- |
| 产品 | 稳定 ID、名称、slug、描述、规格、资料链接 | 分类、规格结构、是否含价格 |
| 批次 | 批次号、产品关联、报告关联 | 库存是否按批次、可公开信息 |
| 检测报告 | 文件 ID、关联批次、发布状态 | 报告权限、版本、有效性说明 |
| 询价 | 产品、需求数量、联系方式、状态 | 必填项、隐私说明、处理流程 |

库存、价格和发货时效只在有明确数据源时展示。报告不存在时使用“暂无报告”等真实状态，不生成替代检测结论。

## 前端需要处理的状态

加载中、结果为空、请求失败、无访问权限、数据不可用。不得用硬编码的成功提示代替服务端处理结果。

## 确认与变更流程

1. 后端在 docs/handoffs/backend.md 提出数据和接口方案。
2. 前端核对页面需求，记录缺失状态或字段。
3. 集成负责人更新本文件，双方基于同一提交开发。
4. 后续变更记录兼容性、影响页面和验证方法。
