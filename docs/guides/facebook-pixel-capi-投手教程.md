# Facebook 像素 + 转化 API（CAPI）接入教程（给投手）

适用：VialCove 平台所有店铺（主店和各子店）。每家店在自己的店铺后台单独设置，互不影响。
店铺端已经内置了 Facebook 像素和 Conversions API，**不需要装任何插件、不需要改代码、不需要 GTM**，只要把 Meta 后台的两样东西填进店铺后台：像素 ID 和访问口令。

---

## 一、先在 Meta 这边准备三样东西

全部在 **Meta 商务管理平台（business.facebook.com）→ 事件管理工具（Events Manager）** 里操作，需要对该像素有管理员权限。

### 1. 像素 ID（Pixel ID / 数据集 ID）
事件管理工具 → 左侧「数据源」→ 选中你的像素（现在 Meta 叫“数据集”）→ 「设置」标签 → 最上方就是 **数据集 ID**，一串 15–16 位数字。复制下来。
没有像素就点「关联数据源」→「网站」→ 新建一个，名字随意（建议用店铺域名）。

### 2. 转化 API 访问口令（Access Token）
同一个「设置」页往下拉 → **「转化 API」** 区块 → 「手动设置」→ 「生成访问口令（Generate access token）」。
- 生成后只显示一次，马上复制保存。
- 口令很长（200 多个字符，以 `EAA` 开头），完整复制，前后不要带空格。
- 一个像素一个口令；换像素要重新生成。

### 3. 测试事件代码（Test Event Code，可选但强烈建议）
同一像素 → 「测试事件（Test events）」标签 → 页面上有一串 `TEST12345` 这样的代码。调试时用，调完要删掉。

## 二、填进店铺后台

1. 登录店铺后台（总后台 → 店铺列表 → 该店名下「进入后台」按钮，或直接用店铺的后台地址）。
2. 左侧 **店铺设置 → 系统设置 → 广告像素**。
3. 找到 **Facebook** 这一块 → 「新增像素」：
   - **像素 ID**：填第一步的数据集 ID。
   - **访问口令（Access token）**：填第二步的口令。填了它服务端才会回传（CAPI）；不填就只有浏览器像素。
   - **关联域名（Linked domain）**：留空 = 这家店的所有域名都回传。只有一家店挂多个域名、不同投手各管一个域名时才需要填。
   - **备注**：随便写，例如投手名字，方便区分。
4. Facebook 区块下面几个选项，按需要：
   - **销售额使用商品金额**：开 = Purchase 的 value 只算商品金额（不含运费、税）；关 = 客户实付总额。一般关。
   - **Content ID 类型**：SPU 或 SKU。如果要跑目录（DPA/Advantage+ 目录广告），要和你上传到 Meta 商品目录的 ID 一致；一般选 SPU。
   - **Content Name 类型**：发什么当 content_name，默认商品标题即可。
   - **上传自定义事件**：开了会额外发 ViewCategory、ViewCart、PlaceAnOrder、Login 几个自定义事件。不做这些的优化可以不开。
   - **购买事件只回传首单**：开 = 每个客户（按账号或邮箱）只有第一笔付款订单算 Purchase，适合只优化新客。
   - **在线订单回传比例**：100% = 全部订单都回传。想“藏一部分销量”可以调低；哪些单被排除按订单号固定，同一单不会重复算。
5. 页面下方「追踪设置」：
   - **测试事件代码**：调试阶段填第三步的 `TEST…` 代码，服务端事件会出现在 Meta 的「测试事件」页。**调完一定清空**，否则会一直是测试状态。
   - **同时回传员工访问（测试用）**：默认店铺员工（已登录后台的人）的访问不回传。你自己要在前台点一遍验证时，临时打开，验证完关掉。
   - **遵守 GPC 信号**：默认开，美国加州等地浏览器带“不要出售/分享”信号的访客不回传。合规要求，别关。
   - **把客户邮箱/手机哈希后放进数据层**：开。服务端回传本来就带哈希后的邮箱、手机，这个是给浏览器端增强匹配用的。
6. 点「保存」。

## 三、哪些事件会回传

店铺按 WooCommerce 真实数据生成统一事件，再翻译成 Facebook 标准事件，浏览器和服务端发**同一个 event_id**，Meta 自动去重：

| 场景 | Facebook 事件 | 浏览器 | 服务端（填了口令） |
|---|---|---|---|
| 任何页面 | PageView | ✓ | 默认关（可在追踪设置里开，会很多请求） |
| 商品页 | ViewContent（带 content_ids、value、currency） | ✓ | ✓ |
| 站内搜索 | Search | ✓ | ✓ |
| 加入购物车 | AddToCart | ✓ | ✓ |
| 进入结账 | InitiateCheckout | ✓ | ✓ |
| 填写支付信息 | AddPaymentInfo | ✓ | — |
| 下单成功页 | Purchase（value = 订单金额，currency、content_ids、num_items） | ✓（每单只输出一次） | ✓ 订单第一次变成“处理中/已完成/保留”时发 |
| 注册 / 登录 | CompleteRegistration / Login（自定义） | ✓ | — |

服务端回传带的匹配参数：客户 IP、浏览器 UA、`_fbp`、`_fbc`（从广告点进来时链接上的 fbclid 会自动存成 _fbc）、SHA-256 哈希后的邮箱、手机、客户 ID。都是哈希后才离开服务器。

**Purchase 以服务端为准**：客户没付款、订单停在“待付款”不会发 Purchase；付款成功（支付回调把订单改成处理中）才发。所以 Meta 里的 Purchase ≈ 实际付款单，和店铺后台订单数差一点是正常的（去重、GPC 访客、拦截器等）。

## 四、验证（务必做一遍）

1. 店铺后台填好「测试事件代码」并打开「同时回传员工访问」，保存。
2. 打开 Meta 事件管理工具 → 该像素 → 「测试事件」页，保持打开。
3. 用手机或电脑浏览器打开店铺前台：看首页 → 点一个商品 → 加购 → 进结账。
4. 「测试事件」页应实时出现 PageView、ViewContent、AddToCart、InitiateCheckout，每个事件旁边能看到**浏览器**和**服务器**两条来源、同一个事件 ID，并标“已去重”。只看到浏览器没有服务器 = 口令没填对或填的是别的像素的口令。
5. 想验证 Purchase：下一单真实付款（或让老板用测试卡），付款成功后 1 分钟内测试事件页出现 Purchase（服务器）。
6. 店铺后台 广告像素 页最下面有「服务端回传记录」（保留 7 天），每条有结果 OK / 失败原因，失败多半是口令过期或像素 ID 不对。
7. **验证完：清空测试事件代码，关掉“同时回传员工访问”，保存。**

## 五、Meta 侧还要做的两件事

### 1. 域名验证（Domain verification）
商务管理平台 → 「品牌安全与适宜性」→ 「网域」→ 添加店铺域名（填根域名，如 `vialcovepro.com`）→ 选 **DNS 验证**，Meta 会给一个 `facebook-domain-verification=xxxx` 的 TXT 记录。
把这个值发给老板（或在总后台 CDN 页面能加 DNS 的人），加到 Cloudflare 该域名的 DNS → 类型 TXT、名称 `@`、内容照抄。几分钟后回 Meta 点「验证」。
不做这步：iOS 用户的转化事件不能做汇总事件衡量，Purchase 会少算。

### 2. 事件优先级（汇总事件衡量 / Aggregated Event Measurement）
事件管理工具 → 该像素 → 「汇总事件衡量」→ 「配置网站事件」→ 选已验证的域名 → 最多 8 个事件按优先级排：
`Purchase（开启价值优化）> InitiateCheckout > AddToCart > ViewContent > PageView`，其余按需要。
Purchase 一定排第一并开“价值优化”，不然 iOS 流量只能回传优先级最高的一个事件。

## 六、常见问题

- **事件管理工具里只有浏览器事件，没有服务器事件**：口令没填 / 填错 / 过期。重新生成口令，店铺后台删掉旧像素再新增。
- **Purchase 数量比后台订单少很多**：正常原因是“待付款”不算、GPC 访客不回传、“只回传首单”或“回传比例”开着。检查这两个选项。
- **Purchase 重复**：不会。浏览器和服务端同一 event_id，且每单服务端只发一次。如果看到重复，多半是同一个像素被填了两遍，或 GTM 里也装了一份像素。
- **自己测试的访问把数据搞脏了**：店铺员工（登录后台的人）默认不回传；非员工的自己人在店铺任何地址后面加 `?pc_px_optout=1` 打开一次，这个浏览器以后就不回传（加 `=0` 恢复）。
- **一个店多个投手**：Facebook 区块可以新增多个像素，每个像素可以限定“关联域名”；不限定就全部都发。
- **换像素**：删掉旧的、新增新的，口令也要换成新像素的。删除像素时可以顺便选“删除保存的口令”。

## 七、给老板的部分（投手不用做）
- 域名验证的 TXT 记录：在总后台 → CDN / Cloudflare 里给对应域名加 DNS TXT。
- 各店的像素 ID 和口令由各店投手填在**自己店铺**的后台，总后台不代填。
- 隐私政策页里要写明使用 Meta 像素 / Conversions API（店铺的政策页生成器里有对应条款）。
