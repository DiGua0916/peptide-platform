# Peptide HQ（总后台）

管理所有 VialCove 店铺的总后台。用户 2026-10-27 的要求：

- 一个销售一个店铺，店铺都是用户自己开的；
- 店铺一定连着总后台，没有手动连接这一步。

总后台装在**单独的一个 WordPress** 上，不装在店铺上。店铺装 peptide-core，它会自己接入总后台。

## 第一期做了什么

- **概览**：所有店铺的销售额、已付款订单、客单价、访客、转化率，可以和上一段时间比。
  - 时间可以选今天、昨天、近 7 天、近 30 天。
  - 有每天销售额的柱状图，也可以展开看每天的数字。
  - 每个店铺一行，可以一键进入店铺后台。
- **店铺**：每个店铺的状态、主域名和 HTTPS、版本、商品数、销售账号数、最后检查时间。
  - 可以马上刷新、改名、从总后台移除。
  - 这一页上也有开新店铺时要加的两行。
- **销售账号**：在总后台新建 / 修改 / 停用 / 删除每个店铺的销售账号，包括账号、邮箱、姓名、密码和能用的菜单。
  - 账号保存在店铺上；总后台不保存销售的密码。
- **告警**：每 10 分钟检查一次店铺，问题消失后告警自动关闭。新告警会发邮件给总后台的管理员邮箱。检查这些情况：
  - 店铺连续两次连不上；
  - 连接密钥失效；
  - 域名连不上；
  - HTTPS 不能用；
  - 平时有订单，但已经 48 小时没有订单；
  - 店铺处于“即将开业”模式。

## 店铺怎么接入

开新店铺时，在店铺的 `wp-config.php` 里加两行。这两行在总后台的“店铺 → 开新店铺”里可以复制：

```php
define( 'PEPTIDE_HQ_URL', 'https://总后台地址/' );
define( 'PEPTIDE_HQ_SECRET', '总后台的注册密钥' );
```

接入的过程：

1. 店铺自己生成一个连接密钥（每个店铺不同）。
2. 店铺用注册密钥签名，把连接密钥发给总后台注册。注册在这些时候发生：
   - 进店铺后台时；
   - 每天一次；
   - 店铺的密钥变了时，马上再注册。
3. 总后台列出这个店铺，几秒后第一次检查，并载入最近 31 天的数字。

店铺上没有“总后台连接”页面，没人需要看到或复制密钥。

安全上的几点：

- 注册密钥只能用来“让店铺接入”。冒用它也拿不到别的店铺的数据。
- 已经接入的店铺用新密钥来注册时，新密钥先放着，下次检查能连上才换掉。

## 接口和签名

总后台调用店铺接口：`?rest_route=/peptide/v1/hq/status|summary|login|staff|staff/delete`。

- 签名：`HMAC-SHA256( 店铺连接密钥, 方法 \n 路由 \n 排好序的查询参数 \n 时间 \n SHA-256(请求体) )`，放在 `X-PC-HQ-Time` / `X-PC-HQ-Sign` 头里。
- 以下情况店铺拒绝：时间相差超过 5 分钟、签名不对、同一个签名用第二次。

店铺注册：`POST ?rest_route=/peptide-hq/v1/register`。

- 签名：`HMAC-SHA256( 注册密钥, "register" \n 时间 \n SHA-256(请求体) )`。
- 请求体：`{url, name, key, version}`。

店铺连接密钥在总后台加密保存（sodium，密钥来自总后台 wp-config 的盐值）。顾客的个人信息不经过总后台。

## 本机开发站

- 地址：`http://127.0.0.1:10090/wp-admin/`，账号密码在 `D:\Codex\Sites\vialcove-hq\LOCAL-LOGIN.txt`（只在本机）。
- 启动：双击 `D:\Codex\Sites\vialcove-hq\start-hq.cmd`。
  - 要先在 Local 里启动店铺开发站，因为总后台的数据库 `vialcove_hq` 在它的 MySQL 里。
- 插件目录通过目录联接指向本仓库的 `wp-content/plugins/peptide-hq`。
- 测试：在总后台那个 WordPress 上运行 `wp eval-file wp-content/plugins/peptide-hq/tests/smoke-hq.php`。
